# Brand Voice Guidelines

## Core Tone

**Professional yet approachable** - Expert without condescension

## Tone Principles

### 1. Evidence-Based
- Back every claim with data or label it "anecdotal"
- Use specific proof points (commits, client quotes, certifications)
- No vague promises or unverifiable claims
- Example: "32 commits on work hours automation" not "extensive development"

### 2. No Hype
- Avoid marketing buzzwords and empty superlatives
- Let results speak for themselves
- Honest about limitations and stage (3 months old)
- Example: "We're students building real products" not "industry-leading experts"

### 3. Builder-Focused
- Makers talking to makers
- Share code, architecture, technical decisions
- All projects public on GitHub
- Example: "See our code before you hire us"

### 4. Pragmatic
- Results over promises
- Practical solutions, not revolutionary claims
- Transparency over black-box solutions
- Example: "If you have to do it more than once, automate it"

## Forbidden Words/Phrases

❌ **Never Use These:**
- "revolutionary"
- "game-changing"
- "disruptive"
- "transform your [business/workflow/etc]"
- "paradigm shift"
- "synergy"
- "cutting-edge" (unless referring to actual new tech)
- "industry-leading" (we're 3 months old)
- "proven track record" (only 2 client testimonials)
- "years of experience" (founded July 2025)

## Approved Phrases/Messaging

✅ **Use These Instead:**
- "Fast deployment" (client-verified)
- "Building in public" (GitHub repos)
- "Computer science engineering students"
- "3 months old and here's what we shipped"
- "See our code before you hire us"
- "We teach what we learn, we build what we teach"
- "Paraguay-based, globally focused"
- "No hype, no fake metrics"
- "Professional, fast, and innovative" (client quote)
- "If you have to do it more than once, automate it"

## Writing Style

### Language Level
- **Clear and jargon-free**: Explain technical concepts simply
- **Active voice**: "We built" not "was built"
- **Concise**: Respect reader's time
- **Specific**: Use numbers, examples, proof points

### Sentence Structure
- **Short sentences**: One idea per sentence when possible
- **Varied length**: Mix short and medium for rhythm
- **Bullet points**: Use liberally for scannability
- **Concrete examples**: Always prefer specific to abstract

### Paragraph Length
- **LinkedIn posts**: 3-5 short paragraphs maximum
- **Sections**: 2-4 sentences per paragraph
- **White space**: Use generously for readability

## Content Frameworks

### The "Real X" Pattern
Format: "We're [honest descriptor] and here's [proof]"

Example:
- "We're 3 months old and here's what we shipped: 6 repos, 2 clients, 20 documented patterns"
- "We're students building real products: see our code on GitHub"

### The "Why We X" Pattern
Format: "Why we [choice] and [learning]"

Example:
- "Why we automated our own time tracking first (and what we learned)"
- "Why all our code is public on GitHub (transparency matters)"

### The "How We X" Pattern
Format: "How we [achievement] with [approach]"

Example:
- "How we delivered fast (client-verified methodology)"
- "How we built bidirectional sync with clean architecture"

- 3-month-old startup journey
- Student founders with real projects
- Building-in-public approach

- **Transparent**: All code public, nothing hidden
- **Helpful**: Teaching what we learn
- **Pragmatic**: Evidence over hype
- **Builder-minded**: Code first, talk later

- Secretive or black-box
- Salesy or pushy

### Instead of This ❌

## Proof Point Usage

### Always Include Evidence
- **Client quotes**: Use verbatim, with attribution
- **Numbers**: Commits, PRs, projects, certifications
- **Links**: GitHub repos, live sites, profiles
- **Awards**: NASA challenge, academic achievements
- **Testimonials**: WPG Software, WPG Amenities

### Evidence Format
Good: "32 commits on work hours automation (production-deployed)"
Better: "32 commits on work hours automation, production-deployed with Docker, FastAPI backend, Next.js frontend"

## Call-to-Action Style

### Primary CTAs
- "See our code before you hire us" (GitHub link)
- "Check out our 3 AI courses on the LMS"
- "Read about 20 agentic patterns in our framework"

### Secondary CTAs
- "Follow for more [specific topic]"
- "What's your experience with [specific challenge]?"
- "Share your thoughts in the comments"

### Never Use
- "DM me for details" (too salesy)
- "Limited time offer" (not authentic)
- "Click here now" (too pushy)

## Emoji Usage

**Sparingly and purposefully**

✅ **Acceptable**:
- 🏆 for awards (NASA challenge)
- ✅ for checkmarks/proof points
- ❌ for "don't do this" examples
- 🚀 for launches (use rarely)

❌ **Avoid**:
- Excessive emoji strings
- Emoji in every sentence
- Party/celebration emoji (🎉🎊)
- Generic enthusiasm emoji
