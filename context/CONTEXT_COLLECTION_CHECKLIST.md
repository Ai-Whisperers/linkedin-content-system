## Tips for Efficient Context Collection

### 1. Start with What You Know

Don't overthink. Start with:
- Copy LinkedIn bios (5 minutes each)
- List your repos with quick descriptions (10 minutes each)
- Write up your two main case studies (30 minutes each)
- Profile your team members (15 minutes each)

**Total Time:** 2-3 hours for minimum viable context

### 2. Use Existing Materials

Pull from:
- Current LinkedIn profiles and posts
- GitHub README files
- Project documentation
- Internal notes and docs
- Client presentations

### 3. Don't Aim for Perfect

Context files don't need to be polished. They're raw material for generation. Quick notes are fine.

### 4. Iterate and Expand

Start with minimum (10 files), generate first batch, then add more context for future batches.

## Questions?

**How much detail should each context file have?**
Enough to write 3-5 posts from it. Aim for 200-500 words per file.

**Can I add more context later?**
Yes! Add context anytime. Your next batch will include content based on new context.

**What if I don't have 3 projects yet?**
Document what you have (even if incomplete or pilot stage). Mark metrics as "anecdotal" if not validated.

**What if some repos are private?**
Document them anyway. Just describe what they do, key features, and any shareable metrics.
